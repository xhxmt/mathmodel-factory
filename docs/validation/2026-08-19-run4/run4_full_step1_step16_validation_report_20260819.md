| 自动工作进程没有继承受控运行环境 | 生产 Web 自动进程曾选择旧全局 Codex 和 Claude 回退路径 | 创建项目时固化执行环境回执，所有自动启动和恢复必须复用 |

### 求解任务页面

| 问题 | 观察证据 | 建议 |
| --- | --- | --- |
| job id 被截成相同前缀 | 并发重试和最终可信任务无法区分 | 显示完整可复制 id，并提供详情抽屉 |

| `6/6 receipts paired` 夸大可信度 | 该数字可以和失败任务或已漂移输出同时出现 | 分开展示提交回执、完成回执、当前输出匹配和事件绑定 |
| 历史失败和当前失败混为一个数字 | 替换任务成功后页面仍保留醒目的失败总数 | 拆分历史、已替代、当前未解决和当前可信四种数量 |
| stdout 与 stderr 链接没有鉴权 | 普通顶层链接不带 localStorage 中的 JWT，受保护接口返回未认证 | 用已认证请求获取 Blob URL 或内置文本查看器，禁止把 JWT 放进查询参数 |
| 相对时间被误当成心跳 | 阶段事件年龄和任务运行时长并排显示，健康长任务看起来像卡住 | 增加独立 `last_heartbeat_at`、年龄、阈值和健康状态 |
| 失败协调延迟扭曲任务时长 | 一秒退出的任务在页面显示运行七分钟 | 保存真实子进程开始和结束时间，退出镜像触发立即协调 |
| 长任务没有结构化进度 | 两个 1000 次重采任务只显示 running，无法知道完成数 | 返回已完成数、目标数、当前阶段和最近进度时间 |

## 跨步骤根因

| 根因 | 造成的后果 | 建议的系统修复 |
| --- | --- | --- |
| 静态所有权规则过宽，最终所有者定义不足 | 正常的 Step 5、6、8、9、10、12 产物被误判为早期语义变化 | 以最终生产阶段和持久 job owner 为准，未知路径保持关闭式处理，并为共享产物建立明确规则 |
| 页面缺少单一版本化投影 | 步骤、阶段、状态、证据和时间互相矛盾 | 后端提供修订原子快照，页面一次提交全部组件 |
| 执行环境身份没有固化 | 恢复和自动工作进程可能选错 CLI、模型、服务档位或代码根 | 每次尝试使用不可变执行环境回执，并在启动前验证 |
| 暂停没有控制完整进程树 | 孤儿 Codex 在暂停后继续运行和写文件 | 控制面拥有完整进程组，暂停与终止语义明确分开 |
| 求解证据身份分散 | 共享日志、历史回执、等待挂起和协调延迟影响可信度与可观察性 | job 唯一日志、当前匹配回执选择、事件式终态协调和结构化进度 |
| 错误回退后缺少检查点重验 | 分类器修复只能撤销脏标志，无法恢复已经删除的下游检查点 | 增加带回执的无代理逐步重验与恢复动作 |
| 终审提示与引用定位使用的文本表示不一致 | 原始 `PASS` 在定位阶段降级，聚合来源难读 | 统一规范文本和标准化过程，分开保存四层判断字段 |
| 评审包覆盖检查发生得太晚 | 三个模型调用完成后才发现 Q2、Q3 规范结果链缺失 | 模型调用前做声明级静态覆盖检查，按角色依赖增量重跑 |
